# 社内アプリ

GitHub Pages で配信している社内向けのアプリ置き場です。

| アプリ | 場所 |
|---|---|
| 工事予定のご連絡 | `renraku/` |
| 業務チェックリスト | `index (2).html` |

---

## 工事予定のご連絡

週の○×と作業内容を入れると、お客様へお送りする文面ができます。

```
工事のトークルームに、このアプリのURLを1回だけ貼っておく
        ↓
毎週、業者さんがそのURLを開いて ○×と作業内容を入れる
        ↓
できた文面をコピーして、同じトークルームに貼る
        ↓
プランナーがそのままお客様へ渡す
```

**URLは貼りっぱなしにします。** 毎週送り直す必要はありません。

### ログインもデータベースもありません

トークルームが工事ごとに分かれていて、**誰に向けた話かはその場の全員が分かっている**ので、
アプリが覚えておく必要がありません。入力した内容はトークに貼った文面として残り、
それがそのまま記録になります。

そのため、この画面は次のどれも使いません。

- ログイン
- サーバー
- データベース（Firestore）

壊れるところがほとんど無く、止まる理由もありません。
使う人から見ると、**開いてすぐ入力できる**という違いになります。

以前はこの構成に Firestore とログインを足した版を作りましたが、
トークルームが工事ごとに分かれていると分かった時点で不要になりました
（2026-09-26 に削除。必要になれば git の履歴から戻せます）。

### お客様名と完成予定を、URLに覚えさせる

毎週打ち直さずに済ませるため、**お客様名と完成予定をURLに入れられます。**

1. 画面でお客様名と完成予定を入れる
2. 下の「このトークルーム用のURLを作る」を開く
3. 出てきたURLをコピーして、そのトークルームに貼る

次からは、そのURLを開くだけで宛名が入った状態で始まります。
**宛名の打ち間違いはそのままお客様に届く**ので、一度URLに入れてしまうほうが安全です。

文体・絵文字の有無・コンクリート養生の日数は、**その端末のブラウザ**に覚えます。
他の方の画面は変わりません。

### このリポジトリは公開です

コードは誰でも読めます。したがって次を守ってください。

- **お客様名をコードに書かない。** URLか入力欄から受け取ります
- 鍵やトークンの類は一切置かない（そもそも必要としない作りです）

`npm test` に、それらが紛れ込んでいないかを見るテストを入れてあります。

## 使いかた

### 事務所（最初の1回だけ）

1. https://shingonishimura0729.github.io/soumugyoumukannri/renraku/ を開く
2. お客様名と完成予定を入れる
3. 「このトークルーム用のURLを作る」を開いて、URLをコピー
4. そのお客様の工事のトークルームに貼る

工事が変われば、新しいトークルームでこれを繰り返します。

### 業者さん（毎週）

1. トークルームに貼ってあるURLを開く
2. 作業のある日に ○、休む日に × を押す。作業内容も入れる
3. コンクリート打設や断水があれば「ご注意いただきたい点」に足す
4. 「文面をコピー」を押して、そのトークルームに貼る

## まだできていないこと

- **トークルームへの自動投稿。** 「文面をコピー」して手で貼る運用です。
  自動で送るには LINE WORKS のキーを隠す場所（サーバー）が要るため、
  静的ページだけでは完結しません
- **注意事項だけを送る文面。** 組み立てる部分（`buildNoticeMessage`）はありますが、
  画面につないでいません。急ぎの連絡を別に送りたくなったら足します
- **写真の受け取り。** 入れていません（2026-09-25 決定）

## 開発するとき

```bash
npm test          # テストを流す。npm install は要りません
```

Node の標準機能だけで動くようにしてあります。テストは2つです。

- `tests/domain.test.js` … 日付の計算と文面の組み立て。**文面の形を固定する**ためのもの。
  ここが赤くなったら、受け取るお客様が気づく変化が起きています
- `tests/pages.test.js` … 画面が開いた瞬間に壊れないか（構文・id・import）と、
  公開リポジトリに書いてはいけないものが紛れていないか

ブラウザで動かして確かめるときは、`file://` ではなく簡易サーバー越しに開いてください。
ES モジュールは `file://` では読み込めません。

```bash
npx serve .       # あるいは python -m http.server
```
