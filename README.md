# 社内アプリ

GitHub Pages で配信している社内向けのアプリ置き場です。

| アプリ | 場所 |
|---|---|
| 工事予定のご連絡 | `renraku/` |
| 業務チェックリスト | `index (2).html` |

---

## 工事予定のご連絡

週の○×と作業内容を入れると、お客様へお送りする文面ができます。

```
工事のトークルームに、このアプリのURLを1回だけ貼っておく
        ↓
毎週、業者さんがそのURLを開いて ○×と作業内容を入れる（自動で保存される）
        ↓
できた文面をコピーして、同じトークルームに貼る
        ↓
プランナーがそのままお客様へ渡す

事務所の人が同じURLを開くと、業者さんが入れた内容が出てくる
```

**URLは貼りっぱなしにします。** 毎週送り直す必要はありません。

### ログインはありません。URLが鍵です

トークルームが工事ごとに分かれていて、**誰に向けた話かはその場の全員が分かっている**ので、
現場やお客様を登録する画面は要りません。URLに入っているトークルームIDが、
そのまま「どの工事か」を表します。

入力は Firestore に自動保存され、**同じURLを開いた人が続きを見られます。**
業者さんが入れたものを事務所が見られるのは、この仕組みによります。

- ログインなし。**URLを知っている人は読み書きできます**（そのルームの人が触れるための作り）
- 打ち終わって 0.8 秒後にまとめて保存。1文字ごとには書きに行きません
- 「最終更新 9/28 14:32」を出します。見ているものが古いかどうかを判断できるように

守りは `firestore.rules` にしかありません。要点は
**`allow list` を絶対に許さない**こと。許すと一覧からIDを集められ、鍵の意味が消えます。
`tests/pages.test.js` で見張っています。

### お客様名を、URLに覚えさせる

毎週打ち直さずに済ませるため、**お客様名はURLに入れます。**

1. 下の「このトークルーム用のURLを作る」を開く
2. お客様名を入れる
3. 出てきたURLをコピーして、そのトークルームに貼る

**このURLでないと保存されません。** ルームIDが入っていないURLは、
文面を作ることはできても、入力が残りません。

宛名の打ち間違いはそのままお客様に届くので、一度URLに入れてしまうほうが安全です。

文体・絵文字の有無・コンクリート養生の日数は、**その端末のブラウザ**に覚えます。
他の方の画面は変わりません。

### スマホでの操作について

- ○×を続けて押しても画面が拡大しないよう、`touch-action: manipulation` を入れてあります。
  **`user-scalable=no` は使いません**（見えにくい人が指2本で拡大できなくなるため）
- 入力欄の文字は **16px より小さくしないこと。** 小さいと iPhone が触った瞬間に拡大します

### このリポジトリは公開です

コードは誰でも読めます。したがって次を守ってください。

- **お客様名をコードに書かない。** URLか入力欄から受け取ります
- 鍵やトークンの類は一切置かない（そもそも必要としない作りです）

`npm test` に、それらが紛れ込んでいないかを見るテストを入れてあります。

## 使いかた

### 事務所（最初の1回だけ）

1. https://shingonishimura0729.github.io/soumugyoumukannri/renraku/ を開く
2. お客様名と完成予定を入れる
3. 「このトークルーム用のURLを作る」を開いて、URLをコピー
4. そのお客様の工事のトークルームに貼る

工事が変われば、新しいトークルームでこれを繰り返します。

### 業者さん（毎週）

1. トークルームに貼ってあるURLを開く
2. 作業のある日に ○、休む日に × を押す。作業内容も入れる
3. コンクリート打設や断水があれば「ご注意いただきたい点」に足す
4. 「文面をコピー」を押して、そのトークルームに貼る

## まだできていないこと

- **トークルームへの自動投稿。** 「文面をコピー」して手で貼る運用です。
  自動で送るには LINE WORKS のキーを隠す場所（サーバー）が要るため、
  静的ページだけでは完結しません
- **注意事項だけを送る文面。** 組み立てる部分（`buildNoticeMessage`）はありますが、
  画面につないでいません。急ぎの連絡を別に送りたくなったら足します
- **写真の受け取り。** 入れていません（2026-09-25 決定）

## 開発するとき

```bash
npm test          # テストを流す。npm install は要りません
```

Node の標準機能だけで動くようにしてあります。テストは2つです。

- `tests/domain.test.js` … 日付の計算と文面の組み立て。**文面の形を固定する**ためのもの。
  ここが赤くなったら、受け取るお客様が気づく変化が起きています
- `tests/pages.test.js` … 画面が開いた瞬間に壊れないか（構文・id・import）と、
  公開リポジトリに書いてはいけないものが紛れていないか

ブラウザで動かして確かめるときは、`file://` ではなく簡易サーバー越しに開いてください。
ES モジュールは `file://` では読み込めません。

```bash
npx serve .       # あるいは python -m http.server
```

## ファイルの並び

```
index.html                    入口
renraku/index.html            本体。画面はこれ1枚
assets/js/domain.js           日付の計算と文面の組み立て。画面も保存も持ち込まない
assets/js/store.js            入力の保存と読み込み（Firestore）
assets/js/firebase-config.js  接続先。ここだけを書き替える
assets/css/app.css            スタイル。スマホ前提
firestore.rules               守り。**ここが本体**。コンソールに貼って公開する
tests/                        テスト
```
